# Fragment Philosophy

## Design Principles

Fragment is built on a foundation of calm, respect, and non-directive observation.

### Core Principles

1. **Quiet** — The interface should feel like a quiet mirror, not a dashboard
2. **Respectful** — Users own their data and definitions entirely
3. **Slow** — Weekly interactions, no daily pressure, no streaks
4. **Non-Directive** — Never tells users what to do or how to be
5. **Observational** — Helps users see patterns, not change them

### Product Posture

Fragment's default posture is:

- **Quiet** — Non-intrusive, calm
- **Respectful** — Honors user autonomy
- **Slow** — Encourages reflection over action
- **Non-Directive** — No advice, no optimization, no correction

If a feature feels motivating, optimizing, or corrective — remove it.

### What We Don't Build

Fragment explicitly avoids:

- Goals and habit tracking
- Streaks and gamification
- Productivity metrics
- Personality tests
- Mood tracking
- Advice engines
- Engagement loops
- Notifications

### Success Metrics

Fragment is successful if:

- Users open it infrequently but intentionally
- Users report clarity without instruction
- Users recognize conflicts without being told what to do
- The app remains useful after long inactivity

Success is measured by **return over months**, not daily use.

### Technical Philosophy

- **Local-First** — Data lives on the user's device
- **Privacy-Forward** — No data collection, no tracking
- **Offline by Default** — Works without internet connection
- **Minimal Infrastructure** — No backend required initially
- **Premium Feel** — High polish, minimal complexity

### AI Philosophy

The AI is a **reflective lens**, not an agent:

- Surfaces patterns without interpretation
- Highlights possible tensions without solutions
- Asks neutral questions without leading
- Never gives advice or recommendations
- Never uses clinical or diagnostic language

All inferences are:

- Dismissible
- Reversible
- Non-authoritative
- Ephemeral (not stored as truth)
